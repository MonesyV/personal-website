医院制度智能问答系统

把分散的规章制度变成一套快问题快速答、复杂问题有证据、低质量检索能回退的问答服务。

不是让每个问题都走大模型，而是让每个问题走合适的路径。

医院制度问题高度重复，但复杂咨询又需要语义检索与来源追溯。系统将 FAQ 缓存、意图识别和 RAG 深度问答分层，减少不必要的模型调用。

Problem framing

业务问题不是“做一个聊天框”。

真正的约束是速度、证据、制度边界和知识更新方式。

01

制度散落，关键词不稳定

员工用自然语言提问，原文可能使用另一套正式措辞。只做目录或全文搜索，容易漏掉语义相近的条款。

02

高频问题不应承担完整 RAG 成本

请假、考勤等问题重复度高，先通过 FAQ 与 Redis 处理，可把深度检索留给真正复杂的问题。

03

答案必须能回到制度原文

医疗机构内部制度具有执行约束，生成内容需要展示来源文档，并在证据质量不足时受控回退。

System architecture

三层结构，各自解决一种成本。

FAST ANSWER

FAQ + Redis

MySQL 存储高频问答，BM25 评分达到阈值后直接返回；热点问题进入 Redis，持续加速重复请求。

DEEP ANSWER

BERT + ReAct

三分类意图路由后，由 ReAct Agent 执行检索、观察与质量评分；不足时使用 HyDE 或子查询重试。

KNOWLEDGE

OCR + Milvus

PDF / DOCX / MD 经文本或多模态识别，按父 512 / 子 128 tokens 分块，再用 BGE-M3 稠密与稀疏向量入库。
