Case file 02 · Patient experience

患者就医体验多维情感分类

把患者评论映射为“体验维度_情感极性”联合标签，让自然语言反馈进入可统计、可分派的业务流程。

场景
患者就医评论分类
模型
Chinese BERT · 20 类
服务
Flask REST API
状态
集成代码可检查
“不满意”不是一个可执行结论；等待、沟通、费用才是。

同样的负面情绪可能来自完全不同的服务环节。联合标签同时编码评论指向的业务维度与正负极性，使结果更接近医院管理动作。

  • BERT-base-chinese
  • PyTorch
  • 20 classes
  • Flask
  • Batch API

Label design

10 个维度，分别判断正面或负面。

标签不是抽象情绪词，而是医院能够定位责任环节的体验维度。

医疗技术正面负面
服务态度正面负面
就医流程正面负面
医院环境正面负面
费用感知正面负面
沟通解释正面负面
等待时间正面负面
设备设施正面负面
治疗效果正面负面
隐私保护正面负面

Inference pipeline

从一句评论到一个可编排的分类结果。

INPUT

文本标准化

Flask 接口接收 JSON 文本，先检查字段类型与空值，再交给统一 tokenizer；当前配置最大长度为 32。

MODEL

BERT 表示学习

中文 BERT 编码评论语义，分类头输出 20 类 logits，覆盖 10 个体验维度与两种情感极性。

OUTPUT

联合标签返回

通过 argmax 选择一个“维度_极性”标签，单模型接口或批量模型接口以 JSON 返回结果。

Product integration

分类器不是孤立脚本，而是服务编排的一部分。

01

独立预测接口

POST /api/predict/comment_classification 接收单条评论，校验输入并返回预测类别，错误状态保持统一 JSON 结构。

02

批量模型编排

POST /api/predict/batch 允许一次请求选择多个医疗 NLP 模型，评论分类器通过统一映射参与组合预测。

03

启动时加载模型

服务启动阶段加载词表、BERT 与分类权重并切换到 eval 模式，推理使用 torch.no_grad()。

能力边界：这里是 20 类单标签联合分类，不是真正的多标签同时预测。

当前代码使用 argmax，一条评论只返回一个“维度_极性”组合。如果一条评论同时讨论等待时间和服务态度，现有实现只能选择其中一个主类别。要升级为真正的多标签任务，需要改用独立 sigmoid 输出、BCE 类损失、逐标签阈值和 micro / macro F1 评测。
